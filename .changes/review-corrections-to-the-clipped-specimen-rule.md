Four corrections from an independent review of the change, all defects in it.

**`specimen-clipped` covered plain list blocks only.** The containment walk ran to the document element, and `ComparisonGroups` wraps every grouped card in a horizontal `ScrollView`, which react-native-web renders as `overflow-x: auto`. Any cell inside a grouped card therefore had a scrolling ancestor and could never be reported, while the rule's calibration claimed the whole corpus. The walk now stops at the cell: what matters is whether the *specimen* contains its own overflow, which is a question about the ancestors inside it, not about the catalog's own chrome. Six cells in this corpus sit under such a scroller and were invisible to the shipped version.

**A component that clips itself was reported as the page's defect.** A shimmer sweep, a carousel or a marquee hides its own overflow, so its children cross the cell with nothing scrolling above them. An `overflow-x: hidden|clip` ancestor inside the cell now counts as containment too, alongside `auto|scroll` — the question is whether the specimen handles its own overflow, not which way it handles it. For an animated sweep the old behaviour also depended on which frame the settle landed in, so the finding was not deterministic.

**Invisibility was checked on the element alone.** Content inside an opacity-0 wrapper, a mid-flight exit animation, or a visually hidden node parked offscreen was measured as if it were on screen. The walk now treats an invisible ancestor as invisible content.

**The rule measures horizontal crossings only, and now says so.** A cell's width is what the page allocates and what `specimenSize` controls; its height grows with its content. The README described it as "painting outside its cell", which claimed more than it did.

**`TokenRow` lost its `sampleWidth` default of 280.** Inside a `TokenRowGroup` the measured column wins, so the default cost nothing there — but a row with `notePlacement="right"` standing on its own then sized its sample to its own content, and the notes stopped lining up in a column, which is the thing that placement exists to do. This reaches every consumer on update, with nothing in their repository to explain it. The default is restored.

**A repaired workspace respawned Metro without waiting for the port.** `performRestart` already waits for the port to free before re-spawning, and Errata 7c records why a naive probe is not enough: Metro listens on `[::1]`, so the port reads as free while it is still bound. Respawning on the child's exit event meant Expo could find its own port taken and either prompt — giving up with "Skipping dev server" in a non-interactive shell — or move to another port, leaving the catalog somewhere the dev lock does not name. The respawn now waits for the port, reusing the same probe.

Re-verified after the corrections: 50 pages at 1280 and 1728 report nothing, and with the original `Tooltip` defect restored the rule still reports exactly its three cells at both widths.
