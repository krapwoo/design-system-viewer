Token pages move each token's source and usage text into a "Details ›" side panel, and `MotionSpecimen` can play SwiftUI springs:
- On every token page, a tile or row now shows only the token's value and specimen (and, for an unresolved or native-expression value, that expression). Its source, usage text and provenance open from a "Details ›" link on that token ("Details for 8pt"), in the same side panel as "Notes and API ›". Only one token's panel is open at a time.
  - A light/dark colour pair has one link, and its panel covers both sides.
  - A token with no source, expression, usages or usage text and a provenance line already shown for its whole section has no link.
- New `TokenDetails` component for your own token pages: give it a `title` and any of `kicker`, `expression`, `source`, `usages` (listed in full, never cut to "+N more") and `usageSummary`. `TokenTile` and `TokenRow` take an `action` slot to hold it, and `SidePanelTrigger` takes an `accessibilityLabel`.
- A `tokenDefinition` entry can carry `expression` (its source expression) and `usages` (every `path:line` call site). They show in that token's Details panel as "Expression" and "Used at N sites", so you no longer need to pack a call-site list into `role`. A light/dark pair shows both sides when they differ.
- `MotionSpecimen` accepts a spring written the SwiftUI way, `{ response, dampingFraction }` or `{ duration, bounce }`, as well as stiffness/damping/mass. The curve matches SwiftUI's spring model; when it counts as settled may differ slightly. A spring that barely settles is cut off after 5 seconds.
