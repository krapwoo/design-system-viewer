`doctor --render` now generates into its own `.ds-viewer-render/` directory instead of the `.ds-viewer/` one a running `dev` server owns, so the two never write the same files. Running it beside a catalog you have open no longer disturbs that catalog at all — its update page keeps Check now and Update now working, where before the check replaced the endpoint with its own short-lived one and the open page was left calling a port that had died with it. `init` gitignores both directories.

`doctor --render` also waits for the catalog's sidebar to appear before it starts opening pages, rather than reading the page once as soon as the server answers. A workspace Metro has never bundled before takes longer the first time, and an empty read was reported as a catalog that failed to render.
