Token pages can be built from scanner findings, and say honestly when an app has no tokens:
- New `tokenScale(kind, findings, options?)` builds a `TokenDefinition` for a radius, dimensions, spacing or opacity page from the literals a scanner found inline: one tile per value (the same value written several ways, or used at several sites, is one tile), smallest to largest; `360pt`, `max 360pt` and `min 360pt` are three values; values the code names come first, apart from plain literals of the same number; values that are not fixed come last, grouped as depends on size, depends on state, or other. Optional `scales` split a kind into sub-scales (their section ids are prefixed `scale-`); the same number in two sub-scales is two values. The README has a new "Value scales from scanner findings" section.
- A token entry takes `expressions` (every way the value is written), listed in its Details panel under "Written N ways"; a repeated form counts once.
- A `tokenScale` page with no `provenance: 'named'` finding opens with "No radius tokens yet / These are values written in the app's code, not shared tokens" (singular noun per kind: "No dimension tokens yet"; `showNoTokensNote: false` turns it off). Any `tokenDefinition` can opt in with `showNoTokensNote: true`; existing pages are unchanged.
- A dimension, spacing or radius tile named for its own value (`6pt`) no longer prints the value a second time. This applies to every existing `tokenDefinition` page of those kinds, whether or not it opts in to anything else; an entry named `Small` still shows `8pt`.
- `doctor` gives a hint, `token-page-hand-built`, for a Radius, Spacing, Dimensions or Opacity page in the `Tokens` group that draws its own tiles; it never fails `--ci`. For real named tokens it points to `tokenDefinition` with `provenance: 'named'`, for literals found in code to `tokenScale`. List a page built by hand on purpose in `doctor.handBuiltTokenPages`. A `tokenScale(...)` page, including `{ ...scale, sections: [...scale.sections, mine] }`, is readable by `doctor`, and is listed as not statically validated.
- The starter kit's Radius page is now a `tokenDefinition` of its real `DS_RADIUS` tokens (`provenance: 'named'`), so a new project's first `doctor` run draws no hint for it; it is listed once as runtime-only, as imported tokens are. Radius samples on every `tokenDefinition` page are now square (56×56), so every corner up to 28 draws differently; before, anything over 18 looked like the same pill.
- Dimension, spacing and radius tiles read more cleanly: a capped value named `max 360pt` no longer repeats `360pt` under its name; when a grid's longest value is wider than a tile, its bars are drawn to scale (with a line saying so) instead of all stopping at the same length; and a code-name note such as `BotPendingRequestCard.cornerRadius` wraps after a dot rather than mid-word.
